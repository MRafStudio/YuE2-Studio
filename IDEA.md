# YuE2-Studio - заметки проекта

## Правила стиля (наши, проверять при каждой правке)

- **Тире - только короткое `-`.** Длинные тире не используем нигде: ни в текстах интерфейса и i18n,
  ни в комментариях кода, ни в документации, ни в переписке. Речь о трёх символах: em dash
  (U+2014), en dash (U+2013), horizontal bar (U+2015). Короткое тире ставится с пробелами:
  `слово - слово`. Строки автора, которые мы переносим или переписываем, тоже приводим к короткому
  тире, но смысл и формулировки сохраняем; строки, которых мы не касались, не трогаем вовсе.
- Комментарии в коде - на английском (требование автора), интерфейсные строки - в i18n на пяти
  языках, личные файлы и инструменты - в `.rafstudio/` и `IDEA.md`.
- **Наши интерфейсные строки лежат в `app/i18n/yue2.ts`** (пять языков в одном файле). Файлы
  `en.ts`, `ru.ts`, `zh.ts`, `ja.ts`, `ko.ts` - авторские: там наши ключи не живут, их строки
  не трогаем. Перед правкой строки проверить адрес: `grep -n "<ключ>" app/i18n/*.ts`.

Написание музыки, ремастеры и каверы, караоке с помощью YuE2-Studio - https://github.com/timoncool/YuE2-Studio.git

## Требования автора к правкам - ПРОВЕРЯТЬ ПЕРЕД КАЖДЫМ PR

Автоматическая проверка (все пункты сразу):

```bash
python .rafstudio/preflight.py
```

Итог `READY for a pull request` - можно отправлять; `NOT READY` - покажет, что именно не так.

Ручной список (что именно проверяется):

1. **Один коммит** поверх свежего `upstream/main`, заголовок в стиле Conventional Commits
   (`feat(ui): …`).
2. **В коммите - только исходники фичи.** Никаких личных файлов (этот `IDEA.md`), весов
   (`.gguf`, `.safetensors`, `.onnx`), медиа, баз, ключей, `node_modules/`.
3. **Комментарии в коде - английские.** Русские допустимы только внутри строк-переводов i18n.
4. **Никакого Python/Node и внешних файлов в рантайме** (правило из `AGENTS.md`). Данные для
   интерфейса приходят родным мостом студии (`useBridgeCommand`), а не из файлов на диске.
5. **Локализация на 5 языков**: `en`, `ru`, `zh`, `ja`, `ko` в `app/i18n/yue2.ts`
   (тип выводится из блока `en`, тест `yue2.test.ts` ловит пропущенный ключ).
6. **Гейты репозитория зелёные**: `npx tsc --noEmit -p tsconfig.json` и `npx vitest run`.
7. **CHANGELOG руками не править** - он генерируется из git-истории.
8. Линтера в проекте нет; тесты компонентов автор не практикует (они есть у `services/` и `i18n/`).

Всё, что касается проекта, живёт в проекте: знания, решения и инструменты. Вернулись в репу -
прочитали её файлы, и всё понятно, ничего держать «в голове» не нужно. В ветке с фичей папка не

`rafstudio/tooling`.

| Файл | Зачем |
|---|---|
| `.rafstudio/preflight.py` | **проверка требований автора перед PR**: `python .rafstudio/preflight.py` → «READY» |
| `.rafstudio/restore.py` | восстановить правки этой ветки из патча в любой копии репы: `--root <копия>`, `--check` |
| `.rafstudio/notify.py` | журнал агента для человека (`.jsonl` + `.html` в `data` студии) |
| `.rafstudio/patches/` | патчи ветки (пересоздаются: `git format-patch upstream/main..HEAD -o .rafstudio/patches`) |
| `.rafstudio/components/` | копии компонентов этой ветки (для `restore.py`) |

**Обновление ветки `rafstudio/tooling`** (после новых правок): отдельная рабочая копия, копируем
туда `.rafstudio/` и `IDEA.md`, коммитим, пушим, копию убираем:

```bash
git worktree add ../YuE2-Studio-tooling -b rafstudio/tooling fc23f9a   # ветка main
cp -r .rafstudio IDEA.md ../YuE2-Studio-tooling/
cd ../YuE2-Studio-tooling && git add -f .rafstudio IDEA.md && git commit -m "chore(project): …" && git push origin HEAD
cd - && git worktree remove --force ../YuE2-Studio-tooling
```
В рабочей копии фичи эти файлы остаются неотслеживаемыми (`.git/info/exclude`) - иначе `preflight`
справедливо забракует pull request: у автора правило «в коммите только исходники фичи».

## Почему у партии (стема) убраны пункты из контекстного меню

Решение проекта (`732a397`, `9baf44e`) - чтобы не «вернуть как было» потом:

1. **Технически бессмысленно.** Стем - уже результат разделения: у барабана нет своих барабанов,
   баса и вокала, отделять от него нечего. Повторное разделение - это «копии копий»: мусор в
   библиотеке, лишние файлы на диске и минуты счёта на GPU.
2. **У партии нет своего промпта.** Она не рождалась из style+lyrics, поэтому «Повторить промпт»
   подставил бы промпт родителя (или пустоту), а «Перерендерить» пересоздал бы не то, что видно на
   экране. Это уже не бесполезно, а вводит в заблуждение.
3. **Продукт не должен показывать тупики.** Формулировка требования: «такой пункт меню должен либо
   отсутствовать в принципе (предпочтительно), либо хотя бы не быть доступным».
4. **Скрываем, а не `disabled`.** Скрытие - уже паттерн автора (караоке появляется только при
   выполнении условий); серый пункт без пояснения читается как поломка интерфейса.
5. **В панели «Инструменты» - текст, а не пустота** (`stemsPartCannot`): тот список трека общий для
   MIDI, редактора, обработки и транскрипции, где партия - нормальный выбор, и «выключенная» кнопка
   выглядела бы как сбой.
6. **Что осталось и почему:** редактор, видео, MIDI, партитура, скачать, удалить, в плейлист -
   всё это работает с партией как с обычным аудио.

Все входы закрыты (их было три!): меню трека, панель «Инструменты», панель «Детали песни»
(там же лежал легаси-путь через `demucs-web` - `extractStems`). Признак партии берётся из БД:
`metadata.derived.tool === 'stems'` → `isPart(song)` в `app/components/songParts.tsx`.

**Сборка своей версии интерфейса (кратко).** Rust + MSVC нужны только для exe: `rustc/cargo`
стоят в пользовательском профиле Windows (`%USERPROFILE%\.cargo`), а НЕ в папке, которую может
перезаписать установщик. `npx tauri build --no-bundle` из `desktop/` собирается ~4 минуты и кладёт
`desktop/src-tauri/target/release/YuE2-Studio.exe` (~61 МБ, интерфейс вшит). Своя сборка
копируется в портативную папку студии рядом с оригинальным `YuE2-Studio.exe` под именем
`YuE2-Studio-raf.exe` (оба держим для сравнения). Грабли MSYS (PATH по `:`,
RUSTUP_HOME/CARGO_HOME только нативно) - в скилле `yue2-studio-build`. **Собирать и запускать
exe - только по прямому указанию владельца студии.**

## Концепция: Workspace = «сессия работы»

**Замысел:** рабочее пространство - это сессия, внутри которой собирается всё, что связано с текущей
работой. Сессия живёт сколько угодно, может содержать сотни треков с партиями (стемы), MIDI, караоке,
референсы - всё, что делается на странице «Создать». Завершение сессии - перенос её в архив
(библиотека всех воркспейсов). Файлы при этом никуда не переезжают: у объектов просто есть `workspace_id`.

**Решено:**

| Вопрос | Решение |
|---|---|
| Что показывает SongList на «Создать» | Только активную сессию; переключение «Сессия / Библиотека» - кнопками на панели **АЛЬФА** |
| Треки вне сессии | Сессия обязательна ВСЕГДА: нет активной - MCP-агент и генерация требуют создать сессию (с именем) либо возвращают ошибку |
| Сколько сессий | Одна активная; список сессий открывается кнопкой на панели АЛЬФА - активировать существующую или создать новую |
| Обозреватель сессий | Пятая вкладка **«Сессии»** на странице «Библиотека» (Все песни / Понравившиеся / Плейлисты / Импорт / Сессии) |
| Переключение сессий | Активировал другую - **старая остаётся открытой**; в архив только по кнопке «Закрыть сессию» |
| Уникальность имени | **Автосуффикс** при коллизии: «Рок», «Рок (2)», «Рок (3)» |
| Старые треки (7 шт.) | При первом запуске **создать сессию «Импорт»** и привязать к ней всё существующее |
| Стемы в списке | **Свёрнуты под родительской песней**; при раскрытии - сдвиг вправо (~1 см), а в освободившемся месте иконки стемов (бас, гитара, барабаны, пиано, вокал, прочее) |
| Лайки | **Перенести в БД** (привязать к песне) - переживут смену профиля и машины |

**Терминология (принята):**

- Кнопка завершения - **«Закрыть сессию»** (не «отправить в архив»).
- В списке сессий у каждой - кнопка **«Открыть сессию»**, делающая её активной.
- **Открытая сессия = текущая.** Все остальные - закрытые. Открыта всегда одна.
- **Флаг «нет открытой сессии»** = нет идентификатора активной сессии → генерация через MCP
  невозможна, требуется сначала открыть/создать сессию (ошибка с таким текстом).

**Подтверждение генерации из MCP (важно):**

Даже когда сессия открыта, MCP-запрос на создание трека должен сначала прийти в студию
**модальным окном**, где пользователь подтверждает создание в текущей сессии или отклоняет.
Варианты ответа:

- **Разрешить один раз** - только этот трек;
- **Разрешить всегда для этой сессии** - больше не спрашивать в рамках открытой сессии;
- **Выбрать другую сессию** - переключиться и создавать в ней;
- отклонить (трек не создаётся).

**Как это реализуемо (проверено в коде):** готовой команды «спроси пользователя» у моста НЕТ
(в `useBridgeCommand` есть только `notify`, `create_*`, `player_*`, `library_*`, `video_*`,
`equalizer_*`, `visualizer_*`, `winamp_*`, `navigate`, `open_settings`). Но есть всё нужное,
чтобы добавить по-авторски: UI-компонент `ConfirmDialog` (уже используется в `App.tsx`),
паттерн моста `useBridgeCommand` и серверный `Bridge` (`broadcast` + ожидание ответа окна
через `oneshot`). Значит: новая команда моста + новый MCP-инструмент, а окно рисует модалку.

**Технические решения (минимум новых сущностей, без миграций):**

- **Таблица `workspaces`** через `CREATE TABLE IF NOT EXISTS` (`id`, `name`, `description`,
  `created_at`, `updated_at`, `closed_at`; `closed_at IS NULL` = открытая, иначе архив).
- **Привязка песни к сессии** - метка `workspace_id` в `metadata_json` (как автор хранит всё
  расширяемое), а не новая колонка: миграция не нужна, старые библиотеки подхватываются сами.
- **Лайки** - `liked` в `metadata_json` той же песни (одна точка хранения, не плодим таблицы).
- **Существующие лайки** из `localStorage` (`yue2-studio-liked-song-ids`) один раз переносятся в БД.
- **MCP**: добавить инструменты `workspace_list`, `workspace_create`, `workspace_open`,
  `workspace_close`, `workspace_get`; `song_create` и прочие генераторы без активной сессии -
  ошибка с просьбой создать сессию.
- **Стем-иконки** (lucide): барабаны, бас, гитара, пиано, вокал, прочее.

**Панель АЛЬФА** (верхняя панель над SongList): кнопка списка сессий + переключатель
«Сессия | Библиотека» + колокольчик (журнал сообщений) + разделители.

**Ширина списков (решено):** ограничение ширины колонки оставляем (длинные строки текста плохо
читаются на широком экране), но **центрирование убрано** - карточки прижаты к левому краю колонки,
как и панель АЛЬФА с поиском (`w-full min-w-0 max-w-5xl`, без `mx-auto`).

**Идея на будущий разбор дизайна:** на очень широких экранах (2K/4K) карточки не растягивать,
а **добавлять справа постоянно открытые полезные панели** - то есть использовать ширину под
инструменты, а не под удлинение строк.

**Архитектурная опора концепции (проверено в коде):**

- одна БД `library.sqlite`, файлы в `data/media|midi|karaoke`, связь по `song_id` - ничего не переезжает;
- производные уже связаны с родителем через `metadata.derived.from` - сессия накрывает стемы, MIDI,
  караоке и версии аудио каскадом;
- миграций у автора нет by design (`CREATE TABLE IF NOT EXISTS` + расширения в `metadata_json`) -
  таблицу сессий добавляем тем же способом, старые библиотеки подхватят её сами;
- пагинации нет ни в сервисе, ни в UI - ещё один довод, что список на «Создать» = активная сессия.
